> 2. **ไม่มีปุ่ม Bulk Actions แบบ dropdown** — ปุ่มตัดสินรายบรรทัด (Approve / Send for Review / Reject / Split) เป็น `<button>` ระดับบนสุดในแถบเหนือตาราง `pr-item-fields.tsx` ปรากฏเมื่อ `role ∈ {approve, purchase}` และอยู่ในโหมดแก้ไข — **ปุ่มอยู่เสมอแต่ `disabled` จนกว่าจะติ๊กแถว** ไม่ได้ซ่อน
> 3. **ใบร่างเห็นแถวกางเป็นข้อความล้วน** — `PrItemExpand` ถูกส่ง `isDisabled = isDisabled || role !== STAGE_ROLE.PURCHASE` ผู้ขอ (role `create`) จึงแก้ vendor / ราคา / ส่วนลด / ภาษี **ไม่ได้เลย** ทั้งที่กางแถวได้ · ที่ผู้ขอแก้ได้ในแถวกางมีอย่างเดียวคือ **สกุลเงิน** (ผ่าน `CurrencyCell` ซึ่งผูกกับโหมดฟอร์ม ไม่ใช่ role)
> 4. **แถบยอดรวมล่างโผล่เฉพาะใบที่บันทึกแล้ว** — `SummaryFooterBar` render `SummaryBar` ก็ต่อเมื่อ `hasRecord` เป็นจริง หน้า `/new` จึงไม่มียอดรวมให้ตรวจ ต้องทำบนใบที่มี `:id` แล้ว
> 5. **`Add Item` ไม่ถูก disable** — `canAddItem = !!workflow_id` ถูกใช้แค่ใน effect ตอน submit เท่านั้น ปุ่มจริงไม่มี prop `disabled` · ตัวที่ถูก gate ด้วย workflow คือ **รายการสินค้า** (`LookupProductInLocation` รับ `workflowId`) ไม่ใช่ปุ่ม
> 6. **`role` มาจาก backend ไม่ใช่จากสถานะใบ** — `purchaseRequest.role` เป็นตัวตัดสินว่าปุ่มไหนโผล่ ใบ non-draft ที่ role ยังเป็น `create` คือใบที่ถูกตีกลับมาหาผู้ขอ ซึ่งยัง **แก้ได้**
> 7. **ลบได้เฉพาะเจ้าของใบ** — `canDeletePr` (`pr-ownership.ts`) ตัดสินตั้งแต่ตอนกด ไม่เปิดกล่องยืนยันแล้วค่อยเด้ง 403 · `isAdmin` ข้ามได้ และถ้า payload ไม่ส่ง `requestor_id` มาเลยจะ **ไม่บล็อก** ปล่อยให้ backend ตัดสิน — เคสเชิงลบต้องใช้บัญชีที่ไม่ใช่ admin และใบที่มีเจ้าของคนอื่นจริง
>
> **Role/BU** — ใช้ `TEST_USERS` เดิมของสเปก 301: ผู้ขอ (`requestorTest`) สำหรับเคสหน้ารายการ/ใบร่าง/รายการสินค้า, HOD/FC เฉพาะเคสที่ระบุไว้ · BU = `BLAVG`
>
> **ข้อจำกัดของข้อมูล** — เคสที่ต้องมีใบ `in_progress`, ใบของคนอื่น หรือใบหลายหน้า ต้อง seed ล่วงหน้า เคสพวกนี้ระบุไว้ใน Preconditions แล้ว อย่าปล่อยให้ `test.skip` กลืนไปเงียบ ๆ แบบเคสเดิม — ถ้าไม่มีข้อมูลให้ `skip` พร้อมเหตุผลที่อ่านออก

## TC-PR-010101 — ติ๊กใบร่างปนกับใบที่รออนุมัติไม่ได้ — ขึ้นกล่องถามก่อนสลับกลุ่ม
**Priority:** High · **Test Type:** Validation
**Preconditions**
Login เป็นผู้ขอ (BU = `BLAVG`); หน้า `/procurement/purchase-request` tab "My pending" มีใบสถานะ `draft` อย่างน้อย 1 ใบ **และ** ใบสถานะ `in_progress` อย่างน้อย 1 ใบอยู่ในหน้าเดียวกัน
**Steps**
1. เปิด `/procurement/purchase-request` (ค่าเริ่มต้นคือ tab "My pending")
2. ติ๊ก checkbox ของแถวใบร่าง 1 ใบ
3. ติ๊ก checkbox ของแถวใบที่รออนุมัติ 1 ใบ
**Expected**
ขึ้นกล่องยืนยันหัวข้อ "One kind at a time" พร้อมข้อความที่ระบุจำนวนที่ค้างอยู่และกลุ่มเดิม ("You have 1 of Drafts selected. Selecting this one clears them.") และปุ่มยืนยันอ่านว่า "Select Waiting for approval instead" · **checkbox ของแถวที่เพิ่งกดยังไม่ถูกติ๊ก** จนกว่าจะกดยืนยัน กดยืนยันแล้วเหลือแถวที่ติ๊กอยู่แถวเดียวคือแถวใหม่
