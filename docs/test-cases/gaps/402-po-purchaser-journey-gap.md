_เคสที่ **สเปกอัตโนมัติยังไม่ครอบ** เท่านั้น ไม่ใช่แคตตาล็อกเต็มของเส้นทางฝ่ายจัดซื้อ — เคสที่ครอบแล้ว (เปิดหน้ารายการ, สลับแท็บ, ค้นหา/กรอง/เรียง, เปิด wizard ทั้งสองทาง, สร้างร่าง, กด Edit/Save/Cancel, Submit, Delete, Send to Vendor, Close) ถูกทดสอบจริงอยู่ใน `tests/402-po-purchaser-journey.spec.ts` และ `tests/401-po.spec.ts` และมีเอกสารที่ generate ไว้ที่ `docs/user-stories/402-po-purchaser-journey.md` / `docs/user-stories/401-po.md`_

> **ข้อเท็จจริงจาก source ที่คนแปลงเป็นสเปกต้องรู้**
> 1. **PO ไม่มีสถานะ void/cancel เลย** — `PO_STATUS` มีแค่ `draft · in_progress · approved · sent_or_print · partial · closed · completed` (`types/purchase-order.ts:7-15`) และ `PO_STATUS_CONFIG` ก็ประกาศเจ็ดค่านี้เท่ากัน (`constant/purchase-order.ts:3-11`) ⇒ "ยกเลิกใบ" ในระบบนี้มีสองทางเท่านั้นคือ **Delete** (ลบทิ้ง, `use-po-form-handlers.ts:544-552`) หรือ **Close** (`handleClosePo`, `use-po-form-handlers.ts:534-542`) ไฟล์นี้จึงไม่มีเคส "void" และเคส `TC-PO-060832` เขียนตามกติกาจริง — ไม่ใช่ยืนยันว่าฟีเจอร์เสีย
> 2. **ปุ่ม Close บนแถบหัวกับเงื่อนไข canClose ไม่ตรงกัน** — `po-form.tsx:89-93` คำนวณ `canClose` ให้ `approved | sent_or_print | partial` แต่ `po-header.tsx:128-131` วาดปุ่มเฉพาะ `approved | sent_or_print` ⇒ ใบ **partial** ไม่มีปุ่ม Close บนแถบหัว ทางเดียวคือติ๊กแถวในตารางรายการแล้วกด Close ในแถบ bulk (`po-item-fields.tsx:171-176, 313-328`) บันทึกไว้เป็นข้อเท็จจริง เคส `TC-PO-060831` เขียนตามนี้
> 3. **ปุ่ม Submit ขึ้นกับ `role` ที่ backend คืน ไม่ใช่โหมดฟอร์ม** — `po-footer-action.tsx:115-124`: `canSubmit = role === "create"` และซ่อนเมื่อใบถึงปลายทาง (`approved/sent_or_print/closed/completed`) · หลังส่งใบแล้ว backend คืน `role = "view_only"` ให้ผู้สร้าง ทำให้ `canEdit` เป็น false (`po-form.tsx:81-82`) ปุ่ม Edit/Delete/Submit หายหมด — คอมเมนต์ใน `tests/pages/po-approver.helpers.ts:82-87` บันทึกเรื่องนี้ไว้แล้ว เคสที่ต้องการร่างจึง **ต้อง** seed ด้วย `createDraftPOAsPurchaser()` ไม่ใช่ `submitPOAsPurchaser()`
> 4. **"บันทึก" กับ "ส่ง" คนละมาตรฐาน** — schema ยอมให้ `order_qty` และ `price` เป็น 0 เพื่อให้เซฟร่างได้ (`po-form-schema.ts:38-44`) แต่ตอนกดส่งมีชั้นที่สอง `validateSubmitItems` บังคับทั้งคู่ > 0 (`use-po-form-handlers.ts:317-341`) โดย **ยกเว้นแถวที่ `foc_qty > 0`** ทั้งแถว (`use-po-form-handlers.ts:322`) และยกเว้นราคาเมื่อ `is_foc` (`use-po-form-handlers.ts:332`) · กรอกไม่ครบ = **ไม่เปิดกล่องยืนยันเลย** (`po-footer-action.tsx:185-199`) แต่เด้งฟอร์มเข้าโหมดแก้ไขให้ (`use-po-form-handlers.ts:362`)
> 5. **เลือกคลังก่อน แล้วรายการสินค้าจึงกรองตามคลัง** — `location-cell.tsx:9-17` และการเปลี่ยนคลัง **ล้างสินค้าที่เลือกไว้ทิ้ง** (`location-cell.tsx:56-65`) พร้อมล้างจุดส่งของเมื่อคลังใหม่ไม่มี (`location-cell.tsx:67-81`) · แถวใหม่ถูก **prepend ขึ้นบนสุด** ไม่ใช่ต่อท้าย และสืบทอดคลัง/จุดส่งของจากแถวบนสุดเดิม (`po-item-fields.tsx:99-117`)
> 6. **ส่วนลด/ภาษีมีโหมด override** — ปิด override: กรอก % แล้วยอดเงินคำนวณเอง (ช่องยอดเงิน disabled) · เปิด override: ช่อง % ถูกล็อก ช่องยอดเงินกรอกเอง และ seed ด้วยยอดที่คำนวณล่าสุด (`discount-tax-override.tsx:88, 104` · `row-pricing-cells.tsx:178-192`) · ช่อง % ถูก clamp 0–100 ในตัว handler (`discount-tax-override.tsx:93`) · สูตรเดียวที่ใช้ทั้งแถวและแถบรวมคือ `computeLineAmounts` (`lib/line-pricing.ts:24-34`): `subtotal = price × qty` → `net = subtotal − discount` → `tax = net × taxRate/100` → `total = net + tax` (round2 ทุกชั้น)
> 7. **แถบยอดรวมท้ายหน้าไม่ได้อ่านจาก backend** — `po-footer-action.tsx:78-97` บวกผลลัพธ์ของ `computeItemPricing` ทุกแถวเอง แล้ววาดห้าค่า Subtotal · Discount · Net · Tax · Grand total พร้อมรหัสสกุลเงินต่อท้ายค่าสุดท้าย (`po-footer-action.tsx:143-176`) ส่วนลด > 0 แสดงเป็นเลขติดลบสีแดง (`po-footer-action.tsx:152-158`)
> 8. **เพิ่มรายการต้องเลือก workflow ก่อน** — กดปุ่มเพิ่มรายการโดยยังไม่เลือก workflow จะได้ `PoWorkflowRequiredDialog` ซึ่ง **มีปุ่มเดียว ไม่มี Cancel** (`po-workflow-required-dialog.tsx:22-24`) กดแล้วพาไป focus ช่อง workflow (`po-item-fields.tsx:123-129, 417-431`)
> 9. **ชนิดใบคุมว่าแก้อะไรได้** — ใบจาก PR (`po_type = purchase_request`) และใบจาก price list (`pricelist`) ล็อกเนื้อหา **เมื่อพ้นสถานะร่างแล้วเท่านั้น** (`po-form.tsx:193-204`) ยกเว้นเรตแลกเปลี่ยนที่ปลดไว้ (`po-general-fields.tsx:70` — `manualFieldDisabled` ไม่ครอบช่อง `exchange_rate`) · ช่อง workflow ล็อกถาวรหลังพ้นร่าง (`po-general-fields.tsx:72`) แบบ disabled ไม่ใช่ซ่อน
> 10. **ปุ่มส่งอีเมลผูกกับสถานะใบ ไม่ใช่โหมด** — `SEND_EMAIL_STATUSES = approved · sent_or_print · partial · closed · completed` (`po-header.tsx:25-31, 85-87`) และ dialog ถูก mount เฉพาะตอนเปิดจริง (`po-header.tsx:300-307`) · ปุ่ม Print อยู่ในเมนู ⋯ และส่งค่ามาเฉพาะโหมด view (`po-header.tsx:200-211` → `doc-actions-menu.tsx:120-134` → `lib/print-document.ts:65-66` ซึ่งยิง `.../purchase-orders/<id>/print-viewer` แล้วเปิด URL ที่ได้)
