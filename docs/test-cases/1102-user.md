# User Management — Test Cases

_Test-case catalog (documentation only; no automated Playwright spec yet). Authored from the React app module at `routes/system-admin/user`. Follows the TC-ID scheme in `docs/test-id-scheme.md`._

**Module:** User Management
**Frontend route:** `routes/system-admin/user`  •  **URL:** `/system-admin/user` (และ `/system-admin/user/:id`)
**Prefix:** `USR`
**Default role:** Platform Admin (ต้องมี permission `system_configuration.view` + license feature `system_admin.user`)
**Total test cases:** 38

> **หมายเหตุสำคัญสำหรับผู้รีวิว:**
>
> 1. **ไม่มีหน้าสร้างผู้ใช้** — `routes/router.tsx` ลงทะเบียนเฉพาะ `user` กับ `user/:id` ไม่มี `user/new`; คีย์ i18n `systemAdmin.user.add` ("Add User") ยังอยู่ใน `messages/en.json` แต่ไม่มีคอมโพเนนต์ไหนเรียกใช้ และหน้ารายการไม่มีปุ่มเพิ่ม ⇒ แคตตาล็อกนี้ไม่มี section 03 (create) การเพิ่มผู้ใช้เข้าระบบทำจากทางอื่น (invitation) ไม่ใช่โมดูลนี้
> 2. **หน้า detail = หน้า assign** ไม่ใช่ฟอร์มแก้ประวัติผู้ใช้ — แก้ได้ 3 อย่างเท่านั้น: Roles (ติ๊กการ์ด), Department (lookup เลือกได้ค่าเดียว), Locations (ติ๊ก checkbox ในตาราง) ชื่อ/อีเมล/username แก้ที่นี่ไม่ได้ · payload เป็น PATCH แบบ diff (`{add, remove}`) ส่งเฉพาะสิ่งที่เปลี่ยน (`buildUserPatch`)
> 3. **blocker — เคส 04 แก้สิทธิ์ของผู้ใช้จริง** ใน BU ทันที ไม่มี sandbox: ห้ามรันกับบัญชีใน `tests/test-users.ts` (ถอด role/location ออกจะทำให้สเปกอื่นที่ล็อกอินด้วยบัญชีนั้นล้มทันที) และทุกเคสต้องคืนค่าเดิมท้ายเทส
> 4. **blocker — เคส 050002 ลบผู้ใช้จริง** และ **ไม่มี UI สร้างคืน** ถ้าลบผิดคนต้องไปกู้ที่ backend ⇒ ต้องเตรียมบัญชีทดสอบที่ทิ้งได้ไว้ล่วงหน้า (สร้างผ่าน invitation/backend) การมีบัญชีทดสอบได้หมายถึงต้องมีอีเมลจริงที่รับลิงก์คำเชิญได้
> 5. **หลัง Save สำเร็จหน้าจะ `navigate("/system-admin/user")` เสมอ** — จะยืนยันผลต้องเปิด detail ซ้ำ ไม่มีทางอ่านผลจากหน้าที่กด Save
> 6. **Export/Print ทำงานจริงแล้ว** (เดิมเป็นปุ่ม disabled "coming soon") — ยิง `GET /api/config/{bu}/user-application-roles` สองจังหวะแล้วสร้างรายงาน user × role · Export ดาวน์โหลด `user-roles_<YYYY-MM-DD>.csv` (ต้องรอ `waitForEvent("download")`), Print เรียก print ของเบราว์เซอร์ผ่าน iframe ⇒ ใน headless ต้อง stub `window.print` ไม่งั้นเทสค้าง
> 7. **หัวหน้ารายการใช้คำว่า "User Assign"** (`systemAdmin.user.title`) ทั้งที่เป็นหน้ารายการ — assert ตามของจริง อย่าคาดหวังคำว่า "Users" · badge จำนวนขึ้นเฉพาะเมื่อ count > 0
> 8. **`ListToolbar` ของหน้านี้ไม่ส่ง prop `table`** ⇒ ฝั่งขวาของ toolbar (เมนู Sort / Toggle Columns) ไม่ถูก render ต่างจากหน้ารายการอื่นทั้งแอป การเรียงทำได้ที่หัวคอลัมน์เท่านั้น
> 9. **ตัวกรองมี field เดียว (Department) แบบ single-select** และ desktop เปลี่ยนจาก sheet ขวาเป็น **popover สองชั้น**: กด Filter → hover แถว Department (ใต้หัวข้อ "Document") → submenu เด้งซ้ายให้เลือก · มือถือยังเป็น bottom sheet · ทะเบียนแผนกถูกยิงตอน hover ไม่ใช่ตอนเปิดหน้า
> 10. **stat tiles 3 ใบ และบล็อก "Head of Department" ถูกถอดออกแล้ว** — ตัวเลขนับย้ายไปอยู่ข้างหัว section (Assign Roles / Locations) ส่วน Departments ไม่มีตัวเลข
> 11. **โหมดดูของ Departments เป็นข้อความล้วน** ถ้าผู้ใช้ไม่มีแผนกจะ **ว่างเปล่า** ไม่มีคำว่า "Not assigned" (คีย์ `notAssigned` / `memberOf` / `noPrimaryDepartment` ยังค้างใน en.json แต่ไม่มีโค้ดเรียก) — อย่า assert ข้อความเหล่านั้น
> 12. **ข้อเท็จจริงที่กระทบเคส 200001:** `useUserById` โยน `new Error("Failed to fetch user")` (ไม่ใช่ `ApiError`) เมื่อ response ไม่ ok ⇒ `ErrorState` มองไม่เห็นว่าเป็น 404 จึงแสดงข้อความกลาง "Something went wrong" + ปุ่ม "Try again" **ไม่ใช่** "User not found" และไม่มีปุ่มกลับหน้ารายการ ทั้งที่ `UserEditContent` ส่ง `notFoundMessage` กับ `backTo` มาแล้ว — เคสจึง assert ว่ามี ErrorState จริง ไม่ assert ข้อความ notFound
> 13. **Locations โหมดแก้ไขโหลดคลังทั้ง BU** (`perpage: -1`) ตารางสูงสุด `max-h-96` ต้องเลื่อนในกล่อง (หัวตาราง sticky) และตัวเลขข้างหัว section ยังนับเฉพาะคลังของผู้ใช้ ไม่ใช่จำนวนแถว
> 14. **ViewSelector / SaveViewDialog (saved views)** มีบนหน้านี้ แต่เป็น infra กลางของทุกหน้า list และการบันทึก view ทิ้ง record ค้างใน app-config — จงใจไม่ทำเคสในแคตตาล็อกนี้
> 15. **checkbox เลือกแถว (`selectColumn`) มีในตาราง แต่หน้านี้ไม่มี bulk action** ติ๊กแล้วไม่มีอะไรเกิดขึ้น — อย่าเขียนเคสคาดหวังแถบ action หมู่
> 16. **การกันสิทธิ์** อยู่สองชั้น: route คุมด้วย `RouteGuard` (`system_configuration.view` + license `system_admin.user`, admin bypass permission ได้แต่ bypass license ไม่ได้) และปุ่มลบคุมด้วย `useDeleteGate` (`system_configuration.delete`)
