# User Management — User Stories

_Authored from the test-case catalog `docs/test-cases/1102-user.md` (documentation only — no automated spec yet)._

**Module:** User Management
**Frontend route:** `routes/system-admin/user`  •  **URL:** `/system-admin/user`
**Prefix:** `USR`
**Default role:** Platform Admin
**Total test cases:** 26

> **Note on shape:** โมดูลนี้ไม่มีหน้า create/invite ผู้ใช้ใหม่ (ไม่มี `new/page.tsx`). หน้า detail (`/system-admin/user/<id>`) คือหน้า "User Assign" สำหรับกำหนด Roles / ดู Departments / กำหนด Locations ให้ผู้ใช้ที่มีอยู่แล้ว. การ "สร้าง" ในที่นี้จึงหมายถึงการ assign สิทธิ์ ไม่ใช่การสร้าง record ผู้ใช้.

## TC-USR-010001 — หน้า list ของ User โหลดสำเร็จ

> **As a** Platform Admin, **I want** the User list page to load successfully, **so that** I can manage the people in the system.

**Priority:** High · **Test Type:** Smoke

**Preconditions**
ล็อกอินเป็น Platform Admin

**Steps**
1. ไปที่ URL `/system-admin/user`

**Expected**
URL ตรงกับ `/system-admin/user`, title แสดง และ DataGrid (หรือ empty state) ปรากฏภายใน 10 วินาที

## TC-USR-010002 — คอลัมน์ Name / Email / Department แสดงค่าถูกต้อง

> **As a** Platform Admin, **I want** the Name, Email and Department columns to render correctly, **so that** I can identify each user at a glance.

**Priority:** High · **Test Type:** Functional

**Preconditions**
มีผู้ใช้อย่างน้อย 1 รายการ

**Steps**
1. ไปที่หน้า list

## TC-USR-040001 — เข้าโหมด edit แล้วเลือก Role เพิ่มให้ผู้ใช้ save สำเร็จ

> **As a** Platform Admin, **I want** to assign an additional role to a user, **so that** they gain the access that role grants.

**Priority:** High · **Test Type:** CRUD

**Preconditions**
เปิด detail ของผู้ใช้; มี Role ในระบบที่ยังไม่ได้กำหนดให้ผู้ใช้นี้

**Expected**
ระบบส่งเฉพาะ role ใน add, แสดง toast "User updated successfully", navigate กลับ `/system-admin/user`; เมื่อเปิด detail อีกครั้ง Role ที่เพิ่มถูกติ๊ก

## TC-USR-400002 — กรอง Location ด้วยประเภทที่ไม่มีรายการต้องแสดง empty state

> **As a** Platform Admin, **I want** a clear empty state when a location-type filter matches nothing, **so that** I understand why the list is empty.

**Priority:** Low · **Test Type:** Edge Case

**Preconditions**
เปิด detail (โหมด view) ของผู้ใช้ที่มี location แต่ไม่ครบทุกประเภท

**Steps**
1. ดู section Locations
2. คลิก chip ของประเภทที่ผู้ใช้ไม่มี location (ถ้า chip นั้นไม่ถูกซ่อน)

**Expected**
แสดง empty state "No locations match filter" พร้อมคำแนะนำให้ล้าง filter (ระบบซ่อน chip ของประเภทที่นับเป็น 0 อยู่แล้ว จึงทดสอบกรณีกรองแล้วไม่พบ)
